# VK Ads Bridge · ITALIAN SUNRISE

Минимальная рабочая интеграция с VK Ads API. Подготовлена отдельно от действующего парсера VK, не изменяет его файлы и процессы.

## Назначение и ограничения

- Загружать реальные PNG/JPEG и рекламные тексты в существующую группу объявлений.
- Создавать объявления только в статусе blocked.
- Не создавать и не менять бюджет, аудиторию или рекламную кампанию; не включать показы.
- Перед каждой записью требовать, чтобы сама группа в кабинете была заблокирована/остановлена (status=blocked). Если группа активна, программа прерывает работу.
- Предоставить простую команду проверки и список групп.
- Все операции записи требуют явного подтверждения ID группы и переменной VK_ADS_ALLOW_CREATE=1.
- Обратите внимание: объявления и медиа после загрузки остаются в рекламном кабинете. В случае частичной ошибки необходимо проверить результат перед повторным запуском.

Код не означает, что кабинет уже подключён: необходим действующий **API access_token** VK Ads или клиентские OAuth-реквизиты.

## Подключение с токеном агентского кабинета Церебро (сначала только чтение)

1. **Проверьте назначение токена:** нужен токен **доступа к VK Ads API**, а не токен маркировки рекламы (ERID), не VK API пользователя и не токен «парсера Церебро». Токен не отправляйте в чат, сообщения, файл репозитория или скриншот.
2. Откройте [GitHub Actions Secrets](https://github.com/nser9444-lang/vk-parser/settings/secrets/actions) → New repository secret.
3. Введите имя **VK_ADS_ACCESS_TOKEN**, значение — полученный токен. Сохраните. Токен **не нужно** добавлять в Variables или исходный код. В секрете допустимо как голое значение, так и строка с префиксом «Bearer ».
4. Откройте [проверку подключения](https://github.com/nser9444-lang/vk-parser/actions/workflows/vkads-check.yml), нажмите Run workflow, выберите main. Эта команда вызывает **только GET** /api/v2/ad_groups.json и не создаёт объявления, не меняет бюджет и не включает рекламу.
5. В успешном запуске будет `"connected": true`. Если ошибка 401/403 — токен может быть другого типа, просрочен или не иметь доступа к VK Ads. Для выяснения пришлите только **текст ошибки без токена**.
6. Готовый access_token может иметь срок действия. Поскольку нет refresh_token или client_secret, программа сама его продлевать не умеет; при истечении обновите GitHub Secret.

Альтернативный способ (если токен не подходит): получите в ads.vk.com пару VK_ADS_CLIENT_ID и VK_ADS_CLIENT_SECRET и сохраните их в GitHub Secrets. При наличии VK_ADS_ACCESS_TOKEN программа сначала использует его.

## Подготовка объявления после успешного подключения

1. В рекламном кабинете создайте или выберите группу объявлений, остановите её. Проверьте, что она относится к нужной рекламной кампании и у неё есть правильные настройки размещения/аудитории/бюджета.
5. Сверьте требуемые поля пакета (package_id), прежде чем готовить рекламные изображения. Набор размеров изображений и текстовых полей зависит от формата группы. Четыре брендовых адаптации 1:1, 4:5, 16:9, 9:16 НЕ означают четыре автоматически поддерживаемых поля одного объявления.
6. Скопируйте example.json в отдельный файл задания и заполните действительный ad_group_id, ссылку сообщества, имена, тексты и пути к оригинальным креативам. Укажите только поля, допустимые в рекламном пакете. Обязательные размеры icon_256x256 и image_1080x607 — лишь пример из документации для конкретного типа объявления.
7. Поместите PNG/JPEG в папку относительно JSON-задания и проверьте его.

## Команды для локального запуска (Python 3.11+)

Установить зависимости:
    python -m pip install -r vk_ads_bridge/requirements.txt

Проверить данные без сети:
    python vk_ads_bridge/cli.py validate vk_ads_bridge/example.json

Безопасная проверка доступа без вывода информации о кампаниях:
    python vk_ads_bridge/cli.py check

Получить список групп по API (только для локальной диагностики, не публикуйте вывод):
    python vk_ads_bridge/cli.py groups

Создать только остановленные объявления в подтверждённой группе:
    VK_ADS_ALLOW_CREATE=1 python vk_ads_bridge/cli.py upload vk_ads_bridge/job.json --apply --confirm-group-id 1234567

Для Windows используйте переменные среды в PowerShell или GitHub Actions. Результаты каждого этапа сохраняются в папку vkads-receipts. Если запись результата уже существует, повторный запуск такого же пакета отклоняется локально.

## Запуск через GitHub Actions

После включения workflow на основной ветке откройте Actions → VK Ads — добавить остановленные объявления → Run workflow.

Укажите путь к JSON-файлу из репозитория и ID остановленной группы. Каждый запуск проходит проверку форматов, наличие файлов и подтверждение остановки группы. Workflow не хранит секреты в логах или исходниках. Отчёт загрузки сохраняется как артефакт GitHub Actions. Не запускайте одно и то же задание второй раз без проверки кабинета — на новых раннерах нет локального файла-предохранителя.

## Формат задания

example.json — демонстрационный шаблон: ID 1234567 и изображений из примера в репозитории нет; его нельзя публиковать как реальную рекламу.

Обязательные поля: ad_group_id, landing_url, ads[].name, ads[].content (имена полей контента из пакета, пути к локальным изображениям), ads[].textblocks (имена текстовых полей из пакета и объекты с text).

Для рекламы подписки на сообщество часто используют text_2000, title_40_vkads, cta_community_vk=signUp, about_company_115, icon_256x256, image_1080x607. Это пример, а не универсальная схема для всех размещений. VK Ads вправе отклонить несовместимые поля или размеры.
