# VK Ads Bridge · ITALIAN SUNRISE

Минимальная рабочая интеграция с VK Ads API. Подготовлена отдельно от действующего парсера VK, не изменяет его файлы и процессы.

## Назначение и ограничения

- Загружать реальные PNG/JPEG и рекламные тексты в существующую группу объявлений.
- Создавать объявления только в статусе blocked.
- Не создавать и не менять бюджет, аудиторию или рекламную кампанию; не включать показы.
- Перед каждой записью требовать, чтобы сама группа в кабинете была заблокирована/остановлена (status=blocked). Если группа активна, программа прерывает работу.
- Предоставить простую команду проверки и список групп.
- Все операции записи требуют явного подтверждения ID группы и переменной VK_ADS_ALLOW_CREATE=1.
- Обратите внимание: объявления и медиа после загрузки остаются в рекламном кабинете. В случае частичной ошибки необходимо проверить результат перед повторным запуском.

Код не означает, что кабинет уже подключён: необходим действующий **API access_token** VK Ads или клиентские OAuth-реквизиты.

## Подключение с токеном агентского кабинета Церебро (сначала только чтение)

1. **Проверьте назначение токена:** нужен токен **доступа к VK Ads API**, а не токен маркировки рекламы (ERID), не VK API пользователя и не токен «парсера Церебро». Токен не отправляйте в чат, сообщения, файл репозитория или скриншот.
2. Откройте [GitHub Actions Secrets](https://github.com/nser9444-lang/vk-parser/settings/secrets/actions) → New repository secret.
3. Введите имя **VK_ADS_TOKEN_ITALIAN_SUNRISE**, значение — полученный токен. Сохраните. Это имя относится только к проекту ITALIAN SUNRISE: другие кабинеты получат другие имена. Токен **не нужно** добавлять в Variables или исходный код. В секрете допустимо как голое значение, так и строка с префиксом «Bearer ».
4. Откройте [проверку подключения](https://github.com/nser9444-lang/vk-parser/actions/workflows/vkads-check.yml), нажмите Run workflow, выберите main. Эта команда вызывает **только GET** /api/v2/ad_groups.json и не создаёт объявления, не меняет бюджет и не включает рекламу.
5. В успешном запуске будет `"connected": true`. Если ошибка 401/403 — токен может быть другого типа, просрочен или не иметь доступа к VK Ads. Для выяснения пришлите только **текст ошибки без токена**.
6. Готовый access_token может иметь срок действия. Поскольку нет refresh_token или client_secret, программа сама его продлевать не умеет; при истечении обновите GitHub Secret.

В рабочих процессах GitHub токен проекта ITALIAN SUNRISE берётся только из отдельного секрета VK_ADS_TOKEN_ITALIAN_SUNRISE, а внутри программы передаётся как VK_ADS_ACCESS_TOKEN. Для других кабинетов создавайте отдельные секреты и отдельные workflow либо явное переключение по проектам — без автоматического перебора токенов. Локальная CLI по-прежнему поддерживает OAuth-пару VK_ADS_CLIENT_ID/VK_ADS_CLIENT_SECRET при отсутствии VK_ADS_ACCESS_TOKEN.

## Как выбрать правильную рекламную группу (после успешного теста API)

В текущем публичном репозитории нельзя безопасно показывать полный список названий всех рекламных кампаний в логах GitHub Actions. Поэтому выберите нужную группу в интерфейсе VK Ads и скопируйте её числовой ID (или предоставьте ссылку на её настройки).

Для проверки ID без изменений в рекламном кабинете откройте [ITALIAN SUNRISE — проверить рекламную группу](https://github.com/nser9444-lang/vk-parser/actions/workflows/vkads-group.yml), нажмите Run workflow, укажите ID и ветку main. Скрипт выполняет только GET одного объекта и показывает `status`, `package_id` и `safe_to_upload`, но не названия кампаний, бюджеты и персональные данные. `safe_to_upload: true` означает **только**, что группа остановлена (blocked); допустимость конкретных рекламных форматов и права на создание пока должны проверяться отдельно.

Для локальной диагностики можно выполнить `python vk_ads_bridge/cli.py group --id 12345`. Токен должен находиться в переменной окружения `VK_ADS_ACCESS_TOKEN`. Публичные Actions logs не должны использоваться для вывода списка всех рекламных групп.

## Новый основной сценарий: одно объявление в новой группе сообщений

**Кампания ITALIAN SUNRISE:** `42378407` (сообщения). **Существующая группа-шаблон:** `169040836`, пакет `3127`. Существующую группу программа не меняет. Для других целей (подписка) потребуется отдельная конфигурация и проверка пакета.

Порядок:
1. На основании реального поста подготовить текст, юридические сведения и изображения для выбранного формата сообщения. Выбирается реальный товар с указанной в публикации ценой и не менее чем тремя исходными фотографиями. Для VK Ads готовятся **четыре изображения в верхний блок «Изображения»**: 600×600 (1:1), 1080×1350 (4:5), 1080×607 (16:9) и 607×1080 (9:16), плюс иконка 256×256. «Карусель слайдов» не используется. Исходная вещь не перерисовывается, её детали и цвет сохраняются.
2. Сохранить JSON задания по образцу [job_messages_template.json](job_messages_template.json) и пять файлов изображений в указанной папке репозитория. Пример намеренно неполный — файлы отсутствуют, рекламные формулировки не утверждены.
3. До первого применения проверить копируемые настройки исходной группы через [GET-only проверку шаблона](https://github.com/nser9444-lang/vk-parser/actions/workflows/vkads-probe-template.yml). Скрипт не показывает аудиторию и бюджет.
4. Запустить [новый workflow: одна новая группа + одно объявление](https://github.com/nser9444-lang/vk-parser/actions/workflows/vkads-one-ad-group.yml). Указать путь к JSON и подтверждение `CREATE_BLOCKED`. По умолчанию никакой запуск не происходит.
5. Программа сперва проверяет данные и принадлежность группы-шаблона кампании; повторный запуск с тем же названием существующей группы отклоняется. Затем загружает фото, создаёт **новую группу** под кампанией `42378407` со статусом **blocked** и **ровно одним объявлением** со статусом **blocked**, с четырьмя изображениями в блоке «Изображения» и без карусели. После POST скрипт читает объявление и сверяет ID каждого изображения со значениями, полученными при загрузке. Таргетинг и параметры аукциона копируются из исходной группы — их нужно проверить в кабинете перед любым ручным запуском рекламы. Никакие бюджеты, статусы и таргетинги действующих групп не изменяются.
6. Ответ сервера с ID новой группы и объявления сохраняется в Actions artifacts. После создания нужно визуально убедиться в правильном размещении, цене, составе, тексте, маркировке и статусе. Только владелец кабинета решает, когда включать показы.

**Безопасность:** GitHub Actions в публичном репозитории; токен только в GitHub Secret `VK_ADS_TOKEN_ITALIAN_SUNRISE`. Не добавляйте файлы клиентов или другие конфиденциальные сведения в репозиторий. Одновременные ручные запуски сериализуются, но для защиты от повторов требуется проверять существующее имя группы; если первый запуск завершился после POST и до отчёта, проверьте кабинет перед новой попыткой.

**Реальный тест и исправление:** 20.11.2026 в объявлении № 253388295 группы № 169050043 по замечанию пользователя исправлена путаница между «Каруселью слайдов» и основным блоком «Изображения». Все четыре формата присутствуют, слайды карусели удалены, статус заблокирован. [Успешная проверка API](https://github.com/nser9444-lang/vk-parser/actions/runs/44773608283). Теперь основной сценарий запрещает ключи слайдов и проверяет все четыре формата при создании новых объявлений.

**Не запускайте этот сценарий без подготовленного конкретного товара.** Код не создаёт рекламную группу заранее и не расходует бюджет.

## Подготовка объявления после успешного подключения

1. В рекламном кабинете создайте или выберите группу объявлений, остановите её. Проверьте, что она относится к нужной рекламной кампании и у неё есть правильные настройки размещения/аудитории/бюджета.
5. Сверьте требуемые поля пакета (package_id), прежде чем готовить рекламные изображения. Набор размеров изображений и текстовых полей зависит от формата группы. Четыре брендовых адаптации 1:1, 4:5, 16:9, 9:16 НЕ означают четыре автоматически поддерживаемых поля одного объявления.
6. Скопируйте example.json в отдельный файл задания и заполните действительный ad_group_id, ссылку сообщества, имена, тексты и пути к оригинальным креативам. Укажите только поля, допустимые в рекламном пакете. Обязательные размеры icon_256x256 и image_1080x607 — лишь пример из документации для конкретного типа объявления.
7. Поместите PNG/JPEG в папку относительно JSON-задания и проверьте его.

## Команды для локального запуска (Python 3.11+)

Установить зависимости:
    python -m pip install -r vk_ads_bridge/requirements.txt

Проверить данные без сети:
    python vk_ads_bridge/cli.py validate vk_ads_bridge/example.json

Безопасная проверка доступа без вывода информации о кампаниях:
    python vk_ads_bridge/cli.py check

Получить список групп по API (только для локальной диагностики, не публикуйте вывод):
    python vk_ads_bridge/cli.py groups

Создать только остановленные объявления в подтверждённой группе:
    VK_ADS_ALLOW_CREATE=1 python vk_ads_bridge/cli.py upload vk_ads_bridge/job.json --apply --confirm-group-id 1234567

Для Windows используйте переменные среды в PowerShell или GitHub Actions. Результаты каждого этапа сохраняются в папку vkads-receipts. Если запись результата уже существует, повторный запуск такого же пакета отклоняется локально.

## Запуск через GitHub Actions

После включения workflow на основной ветке откройте Actions → VK Ads — добавить остановленные объявления → Run workflow.

Укажите путь к JSON-файлу из репозитория и ID остановленной группы. Каждый запуск проходит проверку форматов, наличие файлов и подтверждение остановки группы. Workflow не хранит секреты в логах или исходниках. Отчёт загрузки сохраняется как артефакт GitHub Actions. Не запускайте одно и то же задание второй раз без проверки кабинета — на новых раннерах нет локального файла-предохранителя.

## Формат задания

example.json — демонстрационный шаблон: ID 1234567 и изображений из примера в репозитории нет; его нельзя публиковать как реальную рекламу.

Обязательные поля: ad_group_id, landing_url, ads[].name, ads[].content (имена полей контента из пакета, пути к локальным изображениям), ads[].textblocks (имена текстовых полей из пакета и объекты с text).

Для рекламы подписки на сообщество часто используют text_2000, title_40_vkads, cta_community_vk=signUp, about_company_115, icon_256x256, image_1080x607. Это пример, а не универсальная схема для всех размещений. VK Ads вправе отклонить несовместимые поля или размеры.
